### LabelImg 启动报错（重要坑）
- 用户执行 `labelImg <images目录> <labels目录>` 报
  `PermissionError: [Errno 13] Permission denied: 'D:\\yolo-practice\\data\\lane\\labels'`
- **根因**：LabelImg 的**第二个位置参数是"预定义类别文件"（一个 .txt）**，不是保存目录。
  传了文件夹后，它执行 `codecs.open(文件夹)` 去读，目录不可读 → Permission denied。
  （`labelImg.py:1529 load_predefined_classes`）
- **正解**：
  1. 建 `data/lane/classes.txt`，内容一行 `lane`（类别名）
  2. 启动 `labelImg D:/yolo-practice/data/lane/images D:/yolo-practice/data/lane/classes.txt`
  3. 打开后 `File → Change Save Dir` 选 `data/lane/labels`
  4. 左侧 `PascalVOC` 按钮切成 `YOLO`（否则存 .xml）
  5. 勾 `View → Auto Save Mode`
- 用 classes.txt 的好处：画框时直接选类别，避免手写出错（如 `Lane` 大写、`lane ` 带空格会变成两个类别）。

    → 补修：`p.drawRect(int(left_top.x()), int(left_top.y()), int(rect_width), int(rect_height))`。
  - **教训**：排查这类"老库+新依赖"问题要 grep **所有** drawXXX 调用，不是报错一处改一处。
  - 改前先备份：`cp canvas.py canvas.py.bak`（改坏可回滚）。
  - 改后 `python -m py_compile <文件>` 做语法检查。

### labelImg 兼容性 bug 完整修复清单（最终版）
**根因**：labelImg 1.8.6 是 **Python 2 时代**代码。Python 2 里 `/` 是整除（得整数），
Python 3 里 `/` 是真除法（得小数）。算出来的值变成 float，而新版 PyQt5 的 Qt 方法只收 int → TypeError 崩。

**修了 7 处**（全部加 `int()` 包裹）：
| 文件 | 行 | 内容 |
|---|---|---|
| `libs/canvas.py` | 526 | `p.drawRect(...)` |
| `libs/canvas.py` | 530 | `p.drawLine(...)` |
| `libs/canvas.py` | 531 | `p.drawLine(...)` |
| `labelImg/labelImg.py` | 965 | `bar.setValue(...)` |
| `labelImg/labelImg.py` | 971 | `self.zoom_widget.setValue(value)` |
| `labelImg/labelImg.py` | 1025 | `h_bar.setValue(...)` |
| `labelImg/labelImg.py` | 1026 | `v_bar.setValue(...)` |

- 504 行 `p.drawPixmap(0, 0, pixmap)` 参数本就是 int，无需改；1171 行 `setValue(int(100*value))` 本就 int。
- **排查方法（可复用）**：grep 所有"需要 int 参数的 Qt 方法"——
  `setValue( / drawLine( / drawRect( / drawEllipse( / drawPolygon( / setFixedSize( / setGeometry( / resize( / move(`,
  逐个确认参数是否为算术表达式（算术结果在 Py3 下是 float）。
- 教训：改源码前先备份。本次 `canvas.py` 备份了（`canvas.py.bak`），`labelImg.py` 忘了备份。
- 用户已崩 3 次（drawLine → drawRect → setValue）。若再崩，建议直接换活跃维护的标注工具
  （X-AnyLabeling 之类，支持 YOLO txt 格式），别在这 2020 年停更的工具上继续耗。
